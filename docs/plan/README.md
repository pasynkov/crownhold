# Crown Hold Development Plan

Проект разделен на фазы, каждая из которых дает тестируемый результат.

## Фазы разработки

### [Phase 1A: Minimal Mock](phase-1a-minimal-mock.md) ⭐ **START HERE**
**Цель:** Создать простейший MCP сервер для проверки интеграции
**Результат:** Один tool работает с Claude Desktop
**Время:** 1-2 дня
**Важно:** Начните с этой фазы для проверки что Claude Desktop вообще видит tools!

### [Phase 1B: Full Mock Services](phase-1b-full-mocks.md)
**Цель:** Создать полноценные mock сервисы для всех платформ
**Результат:** Полностью работающий flow с Claude Desktop (на моках)
**Время:** 3-4 дня

### [Phase 2: Research & API Analysis](phase-2-research.md)
**Цель:** Детально изучить API всех сервисов и выбрать библиотеки
**Результат:** Документация по API, готовность к real интеграциям
**Время:** 1-2 дня
**Почему после моков:** Можем сфокусироваться на API, зная что MCP infrastructure работает

### [Phase 3: Polygon Integration](phase-3-polygon.md)
**Цель:** Интегрировать реальный Polygon testnet
**Результат:** Реальные blockchain операции с USDC на testnet
**Время:** 2-3 дня

### [Phase 4: Kraken Integration](phase-4-kraken.md)
**Цель:** Интегрировать Kraken API
**Результат:** Реальные операции на Kraken (депозиты, трейды, выводы)
**Время:** 3-4 дня

### [Phase 5: Wise Integration](phase-5-wise.md)
**Цель:** Интегрировать Wise API
**Результат:** Реальные международные переводы через Wise
**Время:** 2-3 дня

### [Phase 6: End-to-End Integration](phase-6-e2e.md)
**Цель:** Полный workflow от начала до конца
**Результат:** Протестированный полный цикл с реальными API
**Время:** 2-3 дня

### [Phase 7: Production Hardening](phase-7-production.md)
**Цель:** Подготовка к продакшн использованию
**Результат:** Production-ready система с мониторингом
**Время:** 3-5 дней

## Общее время разработки

**Оптимистичная оценка:** 17-22 дня
**Реалистичная оценка:** 22-27 дней
**С резервом:** 27-32 дня

## Новая структура: Почему Research после моков?

**Старый порядок:**
```
0. Research → 1. Mocks → 2. Integrations
Риск: Тратим время на research, но не уверены что MCP вообще работает
```

**Новый порядок:**
```
1A. Minimal Mock → 1B. Full Mocks → 2. Research → 3. Integrations
Преимущество: Проверяем integration за 1 день, потом углубляемся в API
```

**Логика:**
1. **Phase 1A (1 день):** Быстрая проверка что Claude Desktop + MCP работает
2. **Phase 1B (3-4 дня):** Полная mock инфраструктура, тест всех workflows
3. **Phase 2 (1-2 дня):** Теперь детально изучаем API, зная что фундамент работает
4. **Phase 3-7:** Real интеграции без сюрпризов с MCP

## Принципы разработки

1. **Validate early** - проверяем Claude Desktop интеграцию в первые 1-2 дня
2. **Тестируемость после каждой фазы** - каждая фаза дает работающий результат
3. **Моки перед реальными API** - сначала эмуляция, потом интеграция
4. **Research после proof-of-concept** - изучаем API когда уверены в infrastructure
5. **Testnet перед mainnet** - всегда тестируем на testnet/sandbox
6. **Малые суммы** - начинаем с минимальных сумм
7. **Подробное логирование** - логируем все операции
8. **Документирование прогресса** - обновляем документацию по мере разработки

## Критерии готовности фазы

Фаза считается завершенной, когда:
- ✅ Написан и работает код
- ✅ Добавлены тесты
- ✅ Обновлена документация
- ✅ Протестировано вручную
- ✅ Залогированы все операции
- ✅ Готов переход к следующей фазе

## Риски и митигация

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Claude Desktop не видит tools | Средняя | Phase 1A проверяет это за 1 день |
| API недоступен/изменен | Средняя | Документировать версии API, использовать sandbox |
| Нехватка средств на testnet | Низкая | Использовать faucet, просить в сообществе |
| Сложности с MCP protocol | Низкая | Phase 1A решает это до больших инвестиций |
| Проблемы с async операциями | Высокая | Тщательное тестирование polling, timeout'ов |
| Безопасность credentials | Высокая | .env файлы, никогда не коммитить secrets |
