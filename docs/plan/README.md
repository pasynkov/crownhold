# Crown Hold Development Plan

Проект разделен на фазы, каждая из которых дает тестируемый результат.

## Фазы разработки

### [Phase 0: Research & API Analysis](phase-0-research.md)
**Цель:** Изучить API и выбрать технологии
**Результат:** Документация по API, выбранные библиотеки
**Время:** 1-2 дня
**Статус:** ✅ Завершена

### [Phase 1A: Minimal Mock](phase-1a-minimal-mock.md)
**Цель:** Создать простейший MCP сервер для проверки интеграции
**Результат:** Один tool работает с Claude Desktop
**Время:** 1-2 дня
**Важно:** Начните с этой фазы для проверки что Claude Desktop вообще видит tools!

### [Phase 1B: Full Mock Services](phase-1b-full-mocks.md)
**Цель:** Создать полноценные mock сервисы для всех платформ
**Результат:** Полностью работающий flow с Claude Desktop (на моках)
**Время:** 3-4 дня

### [Phase 2: Polygon Integration](phase-2-polygon.md)
**Цель:** Интегрировать реальный Polygon testnet
**Результат:** Реальные blockchain операции с USDC на testnet
**Время:** 2-3 дня

### [Phase 3: Kraken Integration](phase-3-kraken.md)
**Цель:** Интегрировать Kraken API
**Результат:** Реальные операции на Kraken (депозиты, трейды, выводы)
**Время:** 3-4 дня

### [Phase 4: Wise Integration](phase-4-wise.md)
**Цель:** Интегрировать Wise API
**Результат:** Реальные международные переводы через Wise
**Время:** 2-3 дня

### [Phase 5: End-to-End Integration](phase-5-e2e.md)
**Цель:** Полный workflow от начала до конца
**Результат:** Протестированный полный цикл с реальными API
**Время:** 2-3 дня

### [Phase 6: Production Hardening](phase-6-production.md)
**Цель:** Подготовка к продакшн использованию
**Результат:** Production-ready система с мониторингом
**Время:** 3-5 дней

## Общее время разработки

**Оптимистичная оценка:** 15-20 дней
**Реалистичная оценка:** 20-25 дней
**С резервом:** 25-30 дней

## Принципы разработки

1. **Тестируемость после каждой фазы** - каждая фаза дает работающий результат
2. **Моки перед реальными API** - сначала эмуляция, потом интеграция
3. **Testnet перед mainnet** - всегда тестируем на testnet/sandbox
4. **Малые суммы** - начинаем с минимальных сумм
5. **Подробное логирование** - логируем все операции
6. **Документирование прогресса** - обновляем документацию по мере разработки

## Критерии готовности фазы

Фаза считается завершенной, когда:
- ✅ Написан и работает код
- ✅ Добавлены тесты
- ✅ Обновлена документация
- ✅ Протестировано вручную
- ✅ Залогированы все операции
- ✅ Готов переход к следующей фазе

## Риски и митигация

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| API недоступен/изменен | Средняя | Документировать версии API, использовать sandbox |
| Нехватка средств на testnet | Низкая | Использовать faucet, просить в сообществе |
| Сложности с MCP protocol | Средняя | Начать с простейших примеров, изучить документацию |
| Проблемы с async операциями | Высокая | Тщательное тестирование polling, timeout'ов |
| Безопасность credentials | Высокая | .env файлы, никогда не коммитить secrets |
